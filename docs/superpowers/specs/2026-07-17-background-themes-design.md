# 배경 테마 시스템 v1 (미니멀 / 다시마 숲 / 산호초) — 디자인 문서

작성일: 2026-07-17
방향: 아쿠아스케이프(배경)를 **교체 가능한 테마**로 구조화하고, 신규 테마 2종(다시마 숲·산호초)을 제작한다. 기본값은 현재 배경('미니멀')이라 기존 사용자에게는 무변화 하위호환.

## 0. 배경 / 문제

- 현재 배경은 절차적 모래 + 카펫 수초 + 바위/자갈/유목 **단일 구성**이다. 사용자 요청: "배경을 좀 더 풍성하게 — 다시마 숲, 바위, 산호 등. 필요하면 3D 렌더링을 하거나 무료 소스를 찾기", 그리고 최초 요청은 "배경 스킨을 추가로 만들어 교체".
- 단일 배경에 요소를 모두 섞으면 산만해지고(미니멀 원칙 훼손), 테마로 분리하면 각 배경이 뚜렷한 분위기를 가지면서 가림이 싫은 사용자는 미니멀로 돌아갈 수 있다 → **테마 교체형으로 확정**(사용자 승인).
- 이 영역의 최대 리스크는 투명 오버레이 셰이더 함정(CLAUDE.md): 반투명/additive 평면이 바탕화면 위에 수평선·사각형으로 비침. 신규 요소는 alpha-discard 카드와 불투명 메시로만 구성한다.

## 1. 확정된 결정사항

| 항목 | 결정 |
|------|------|
| 구조 | 테마 교체형 (패널에서 선택, localStorage 영속) |
| v1 라인업 | ① 미니멀(현재 그대로, 기본값) ② 다시마 숲 ③ 산호초 |
| 바위 | 별도 테마가 아니라 각 테마의 구성 요소(다시마 숲의 큰 바위, 산호초의 암반) |
| 에셋 방식 | 하이브리드 — 다시마=절차적 셰이더 카드, 바위=절차적 변위 지오메트리, 산호=절차적 1차 → 미학 미달 시 블렌더 GLB(새우 파이프라인) 또는 CC0 소싱으로 격상 |
| 배치 원칙 | 다시마는 뒤쪽·양옆 가장자리 집중, 중앙 밀도 낮게 — "시선은 물고기에 집중" 원칙 유지 |
| 하위호환 | 저장된 themeId 없으면 '미니멀' → 기존 사용자 무변화 |

## 2. 아키텍처 (기존 규칙 준수)

- 테마 데이터는 `src/shared/config.ts`의 `THEME` 상수로: 테마별 `{ id, displayName, sand(색·변주), plants(기존 PLANT.species 형식 배열), hardscape(기존 HARDSCAPE 형식), kelp?, coral? }`. 매직 넘버 금지 원칙 그대로.
- `src/renderer/entities/themeRegistry.ts` 신설 — `plantRegistry`/`speciesRegistry`와 동일한 레지스트리 패턴(타입 안전 조회, 미존재 id는 throw).
- `Aquascape`는 생성자/빌드 함수가 테마 config를 받도록 일반화. `_buildSand/_buildGrassCards/_buildHardscape` + 신규 `_buildKelp/_buildCoral`.
- **테마 전환 = dispose → rebuild.** 요소 수백 개 수준이라 1프레임 리빌드 예상. smoke/수동 측정에서 드랍 확인 시 분할 생성으로 보완(선최적화 금지).
- 영속: `persistence.ts`에 `themeId` 추가(기존 스키마 하위호환 로드).
- UI: `ControlPanel`에 테마 세그먼트 버튼 3개(기존 토글 생성 헬퍼·2열 레이아웃 준수, `:focus-visible`·`aria-label` 포함). 도움말 항목 1줄 추가.
- 신규 요소 파이프 연동(필수): 다시마 셰이더에 `uMoodColor`·`uSceneOpacity` 유니폼(수초와 동일 규약), 산호·바위는 `MeshStandardMaterial` + `applyCausticToStandardMaterial` + `applyWaterDepthToMaterial` + `_opaqueMaterials` 등록(투명 슬라이더 대응).

## 3. 컴포넌트 설계

### 3.1 다시마 (kelp — 절차적, 신규)

- 기존 그래스 카드 시스템의 "키 큰 형제": 세로로 긴 **멀티 세그먼트 리본 지오메트리**(세그먼트 6~10, 폭 ~0.1×높이별 테이퍼) + 인스턴싱.
- 버텍스 셰이더 벤딩: 그래스의 `h01²` 스웨이를 확장해 **누적 곡률**(아래 고정, 위로 갈수록 큰 휨 + 저주파 2차 웨이브)로 다시마 특유의 굽이치는 움직임. 프래그먼트는 그래스와 동일한 alpha-discard + base→tip 그라디언트(짙은 갈록색→올리브).
- 초기 수치(eval 루프에서 조정): 15~25개, 높이 2.5~3.2 유닛(sandY −1.8에서 팁 y≈0.7~1.4), 배치는 x 가장자리·z 뒤쪽 가중 분포 + 중앙 폴오프.
- 순수 헬퍼: `kelpHelpers.ts` — 인스턴스 배치(시드 결정적, 중앙 폴오프), 세그먼트 벤딩 각 계산. TDD.

### 3.2 큰 바위/암반 (절차적 업그레이드)

- 현 정12면체 바위를 **노이즈 변위 로우폴리**(icosahedron subdiv 1~2 + 시드 노이즈 변위 + flat shading)로 업그레이드. 기존 `generateHardscape` 배치 로직 재사용, 테마별 개수/스케일/색만 config로.
- 다시마 숲: 큰 바위 3~5개(어두운 회갈색). 산호초: 낮고 넓은 암반(밝은 석회색).

### 3.3 산호 (절차적 1차 → 격상 경로)

- 3종 절차 생성: **가지 산호**(재귀 분기 튜브, depth 2~3), **뇌 산호**(노이즈 변위 반구), **부채 산호**(alpha-discard 카드 + 잎맥 캔버스 텍스처, 다시마 셰이더 재사용·스웨이 미세).
- 색: 주황/분홍/보라 팔레트, 인스턴스별 변주. 무드 틴트와 곱연산되므로 심야에서도 탁하지 않은지 캡처 확인.
- **격상 기준**: 자체 미학 eval 4/10 미만이거나 사용자 피드백 시 → 블렌더 절차 제작 GLB(새우 파이프라인 `SHRIMP_REPORT.md` 재사용) 또는 CC0 소싱(라이선스·폴리수·스타일 정합 검증)으로 교체. 코드는 "산호 메시 공급자"만 갈아끼우면 되도록 생성 함수를 분리해 둔다.
- 순수 헬퍼: `coralHelpers.ts` — 분기 트리 파라미터 생성(시드 결정적), 클러스터 배치. TDD.

### 3.4 테마 구성 초기값

## 4. 검증

- **TDD(순수 로직)**: `kelpHelpers`(배치 폴오프·벤딩), `coralHelpers`(분기·클러스터), `themeRegistry`(조회·기본값·하위호환 로드), 전환 상태 로직. 기존 446+ 테스트 무회귀.
- **스모크**: `AQUA_SMOKE_THEME` 훅 추가(기존 `AQUA_SMOKE_*` 규약). 테마 3종 각각 캡처 → 픽셀 비교로 "전환이 실제 반영됨" 검증, 콘솔 에러 0, health pass.
- **셰이더 함정 게이트**: 고밝기+밝은 배경 격리 캡처(테마별). additive 금지, 반투명 대형 평면 금지, 다시마/부채 산호는 alpha-discard만 사용.
- **미학**: 비전 eval + 빠른 구현→캡처→재시도 루프(사용자 선호 워크플로). 수치(개수·높이·색)는 spec이 아니라 루프에서 확정.
- **라이브 QA(사용자)**: 테마 전환 체감, 다시마 가림 정도, 산호 색감(무드별), 리빌드 순간 프레임.
